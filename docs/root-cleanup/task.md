# MarketGate Root Cleanup Task

## Role
너는 `pds2225/marketgate` 저장소의 **루트 폴더 구조 정리 담당 개발자**다.

## 최종 목표
현재 기능, 배포, 테스트, API 동작을 그대로 유지하면서 저장소 루트에 불필요하게 흩어진 파일과 폴더를 정리한다.

단순히 파일 수를 줄이는 것이 목적이 아니다.

최종적으로:
1. 루트에는 프로젝트 전체에 필요한 핵심 파일만 남긴다.
2. 문서·임시파일·개발보조자료·스크립트를 목적별 기존 폴더로 정리한다.
3. 기존 경로 참조가 깨지지 않게 수정한다.
4. 비개발자도 루트 구조만 보고 프로젝트 구성을 이해할 수 있게 만든다.

---

## 최우선 규칙

- 기존 구조를 최대한 유지한다.
- 최소 변경 원칙을 적용한다.
- `1기능 = 1작업 = 1검증` 원칙을 지킨다.
- 루트 정리와 관계없는 기능 추가·리팩터링·고도화는 하지 않는다.
- 사용자의 기존 미커밋/미병합 작업을 덮어쓰거나 되돌리지 않는다.
- README/TASK/운영문서가 구조 변경의 영향을 받으면 함께 업데이트한다.
- Windows 기준으로 경로 충돌 및 대소문자 충돌을 고려한다.

## 작업 시작 전 반드시 읽기

아무것도 수정하기 전에 최소한 아래를 읽고 규칙을 파악한다.

- `AGENTS.md`
- `CLAUDE.md`
- `README.md`
- `TASK.md`
- `TASKS.md`
- `.gitignore`
- `vercel.json`
- `.github/` 내 배포/CI 관련 핵심 설정

전체 저장소를 무작정 재귀 탐색하지 말고, 루트 구조와 위 문서에서 필요한 범위부터 확인한다.

---

## 절대 금지

다음 항목은 근거 없이 삭제·이동·rename하지 마라.

- `.git` 관련 파일
- `.github`
- `.env`, `.env.example` 등 환경설정
- `package.json`, lock 파일
- `pyproject.toml`, `requirements*`
- Docker 관련 파일
- `vercel.json` 및 실제 배포 설정
- DB migration 관련 파일
- CI/CD 설정
- 서비스 실행 진입점
- 테스트 설정
- `AGENTS.md`, `CLAUDE.md` 등 AI 작업규칙
- `README.md`, `TASK.md`, `TASKS.md` 등 운영 기준 문서
- import/runtime에서 참조되는 파일
- 외부 배포·자동화에서 참조되는 파일

정체를 정확히 모르는 항목은 삭제하지 말고 `REVIEW_REQUIRED`로 남긴다.

---

# STEP 1 — Baseline 확인

수정 전 다음을 확인한다.

1. `git status`
2. 현재 branch
3. `origin/main` 대비 상태
4. 루트 폴더 파일/폴더 목록
5. 주요 서비스/앱 구조
6. 기존 docs/scripts/archive 구조
7. 루트에 있는 각 파일의 역할

### 출력

```text
[BASELINE]
branch:
working tree:
origin/main relation:
root item count:
existing user changes:
```

기존 변경사항이 있으면 **보존 대상**으로 표시한다.

---

# STEP 2 — 루트 항목 전수 분류

루트의 모든 항목을 다음 중 하나로 분류한다.

### A. KEEP_ROOT
프로젝트 전체에서 루트에 있어야 하는 핵심 파일.

### B. MOVE_DOCS
문서, 조사자료, 설계자료, 작업기록 등.
가능하면 기존 `docs/` 구조를 재사용한다.

### C. MOVE_SCRIPTS
프로젝트 전체용 보조 스크립트.
단, 특정 서비스 전용이면 해당 서비스 하위에 둔다.

### D. MOVE_ARCHIVE
현재 실행에는 사용되지 않지만 삭제 근거가 부족한 과거 자료.
가능하면 기존 `archive/` 구조를 사용한다.

### E. DELETE_CANDIDATE
명백한 임시파일, 중복파일, 생성산출물 등.

### F. REVIEW_REQUIRED
용도나 참조 여부가 불명확하여 자동 변경하면 위험한 항목.

각 항목마다 아래를 기록한다.

| 현재 경로 | 분류 | 제안 경로 | 코드 참조 | 문서 참조 | 배포 영향 | 위험도 | 이유 |
|---|---|---|---|---|---|---|---|

위험도는 `LOW / MEDIUM / HIGH` 중 하나로 표시한다.

---

# STEP 3 — MOVE/DELETE 전 참조 검사

`MOVE_*` 또는 `DELETE_CANDIDATE`로 판단한 항목은 실제 변경 전에 저장소 내 참조 여부를 확인한다.

확인 대상:

- Python import
- JS/TS import, require
- 파일 경로 문자열
- subprocess / shell / PowerShell 실행
- Docker
- GitHub Actions
- Vercel
- 테스트 fixture
- README/TASK/TASKS/운영문서
- Python/Node 설정
- 데이터 로딩 경로
- CI/CD 경로

참조가 확인되면:

1. 이동하지 않거나
2. 이동과 동시에 관련 경로를 최소 수정한다.

**참조 여부를 확인하지 않은 파일은 이동하거나 삭제하지 않는다.**

---

# STEP 4 — 실제 정리

분석만 하고 끝내지 말고, **LOW RISK로 확인된 항목은 실제 정리**한다.

우선순위:

1. 명백한 문서 → 기존 `docs/` 하위
2. 명백한 공통 보조 스크립트 → 기존 `scripts/` 또는 대응 폴더
3. 사용하지 않는 과거 자료 → 기존 `archive/`
4. 명백한 임시 산출물 → 삭제
5. 위험하거나 애매한 항목 → 그대로 유지

### 추가 원칙

- 새 폴더를 무분별하게 만들지 않는다.
- 기존 `apps/`, `services/`, `data/`, `db/`, `docs/`, `ops/`, `scripts/`, `tools/`, `archive/` 구조를 최대한 재사용한다.
- 파일명을 예쁘게 만들기 위한 대규모 rename은 하지 않는다.
- 코드 포맷팅, import 정렬, 변수명 변경은 하지 않는다.

---

# STEP 5 — 경로 보정

파일 이동으로 깨지는 참조만 최소 수정한다.

예:

```text
old/path/file
→
docs/... 또는 scripts/...
```

루트 정리와 관계없는 코드 변경은 금지한다.

---

# STEP 6 — 비개발자용 구조 문서화

정리 후 `README.md` 또는 기존 구조 설명 문서에 현재 저장소 구조를 간단히 반영한다.

예시는 참고용이며 실제 구조를 기준으로 작성한다.

```text
marketgate/
├─ apps/       사용자-facing 앱
├─ services/   백엔드/도메인 서비스
├─ data/       데이터 자산
├─ db/         DB 관련 자산
├─ docs/       문서 및 설계
├─ ops/        운영 관련 자산
├─ scripts/    공통 실행/관리 스크립트
├─ tools/      개발 도구
└─ archive/    비활성/과거 자료
```

존재하지 않는 구조를 문서에 만들어내지 않는다.

---

# STEP 7 — 검증

정리 전후 기능이 동일한지 검증한다.

최소 확인:

1. `git diff`
2. 깨진 경로 참조 검사
3. 영향받은 영역 핵심 테스트
4. build 가능한 프로젝트는 build
5. 기존 workflow에 lint/typecheck가 있으면 해당 범위 실행
6. Vercel/CI/CD 경로 검증

### 테스트 실패 시

- 기존부터 실패하던 테스트인지
- 이번 정리로 발생한 실패인지

반드시 구분한다.

이번 정리 때문에 새로 실패한 것은 수정해야 한다.

---

# 삭제 정책

`DELETE_CANDIDATE`라도 아래 중 하나라도 해당하면 삭제하지 않는다.

- 사용 여부 불명
- 운영/배포 연관 가능성 있음
- 외부 시스템에서 참조할 가능성 있음
- 사용자 자료일 가능성 있음
- git history를 추가로 봐야 판단 가능
- 문서상 역할이 남아 있음

이 경우 `REVIEW_REQUIRED`로 보고만 한다.

---

# 예외/오류 처리

반드시 고려한다.

- dirty working tree
- 존재하지 않는 예상 폴더
- 동일 파일명 충돌
- Windows 대소문자 충돌
- 파일 이동 후 import/path 오류
- 빈 폴더
- 테스트 실행 불가
- dependency 설치 필요
- Vercel/CI 경로 영향

기존 환경을 대규모 변경하여 테스트를 억지로 통과시키지 않는다.

---

# 완료 조건

다음을 모두 만족해야 `PASS`다.

- 기존 기능 변경 없음
- 실행 경로 파손 없음
- 배포 설정 파손 없음
- 이번 변경과 관련된 핵심 테스트 통과
- 루트 구조가 기존보다 단순해짐
- 불필요한 신규 폴더 남발 없음
- README 또는 구조 문서가 실제 상태와 일치
- 사용자 기존 변경사항 보존
- 삭제 근거 없는 파일 삭제 없음

하나라도 확정하지 못하면 `PARTIAL`로 보고한다.

---

# Git 정책

- 기존 사용자 변경을 되돌리지 않는다.
- force push 금지
- history rewrite 금지
- 임의 revert 금지
- unrelated change를 한 커밋에 섞지 않는다.
- 가능하면 루트 정리 변경만 별도 커밋으로 만든다.
- 사용자 요청 없이 main 병합/대규모 후속 리팩터링을 하지 않는다.

# 최종 실행 지시

지금부터 위 순서대로 진행한다.

**분석만 하지 말고 안전성이 확인된 LOW RISK 루트 정리는 실제 수행하고, 경로 보정과 검증까지 완료한다.**

단, `REVIEW_REQUIRED`, `MEDIUM`, `HIGH` 항목은 근거가 충분하지 않으면 자동 변경하지 않는다.
