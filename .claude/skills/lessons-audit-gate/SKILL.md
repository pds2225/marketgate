# A. 전수 점검


## 왜

오답노트는 실제로 틀렸던 것들의 목록이라, 산출물을 전수 대조하는 것이 재발을 막는
가장 싼 방법이다. 트리거 키워드 자동주입은 일부만 걸린다(전수가 아니다). 그래서
제출본·최종 산출물 마감 전에는 **파일 전체를 읽고** 전수 점검한다.

## 절차

1. **`D:\.omc\agent-learning\lessons.md` 를 Read 한다.** 번호 범위를 하드코딩하지
   마라 — 파일에 있는 것이 전부이며, 새로 추가된 교훈도 이 읽기로 자동 포함된다.
   파일은 **구역 3개**로 나뉘어 있다(2026-07-23 재정리). 이번 산출물에 맞는 구역만 본다:
   - **📌 공통** — 항상 본다(일하는 방식·검증 태도).
   - **📄 문서작성** — 사업계획서·이력서·신청서·HWPX·한글 산출물일 때.
   - **💻 개발** — 코드·git·자동화 작업일 때(v_up 위젯·mail·walk 등).
   문서 제출본이면 `공통 + 문서작성`, 코드 작업이면 `공통 + 개발` 이 대상이다.
   구역을 건너뛰었으면 보고에 "해당없음 N건(구역명)"으로 남긴다 — 조용히 생략하지 마라.
2. **교훈을 3종으로 분류**해 산출물에 적용한다:
   - **기계 검증 가능** (색·폰트·크기·줄간격·마커·구조·분량…) → 반드시 **실측**한다.
     로직 리뷰·기억으로 "통과"라 말하지 않는다(L005).
   - **내용 검증** (날조0·메타문구·표현·선별 기준…) → 산출물 텍스트를 실제로 읽고 대조.
   - **작업방식** (질문 규칙·버전 규칙·git…) → 이번 작업 과정이 지켰는지 회고.
3. **결과를 체크리스트로 보고**: 준수 ✅ / 위반 ❌ / 해당없음 — . 해당없음이 많아도
   생략하지 말고 "N건 해당없음(사유 요약)"으로 집계는 남긴다.
4. **위반은 보고만 하지 말고 즉시 수정**한다(§0 실사용 우선). 수정 후 해당 검증을 재실행.
5. 렌더링 가능한 산출물(HWPX·DOCX·PDF)은 **실제 렌더로 눈검증**까지가 완료다(L005·L031).
   XML 순서 ≠ 렌더 순서일 수 있다 — 결함 판정은 렌더에서 확정한다.
6. **재생성이면 회귀 전수점검 의무(L077)**: 같은 산출물을 다시 만들었으면(버전 업·방식 전환)
   직전 확정판에서 되던 것이 유지되는지 반드시 대조한다 —
   `py -3.11 D:\auto_write\scripts\submission_regression_check.py --dir <제출본> ...`
   (페이지수·서명 이미지·필수값·금지값·zip, exit 0/2) + 굵기·정렬·서명 위치는 크롭 눈검증.
   자동 텍스트 검출은 rhwp 글리프 분할로 굵기를 못 잡는다 — "검출 안 됨 ≠ 정상"이므로 눈으로 본다.

## 기계 검증 도구 (auto_write 산출물 기준)

| 점검 | 도구 |

# B. 새 교훈 등록 (marketgate 버전에서 합침)


> 원칙: **같은 결함이 두 번 다시 게이트를 통과할 수 없게 만든다.**
> (auto_write의 lessons-audit-gate 전역 스킬을 marketgate 문서·설계 단계에 맞게 이식한 프로젝트 스킬)

## 원장

- 위치: `docs/LESSONS.md` — `L###` 일련번호, append-only(항목 삭제 금지)
- 형식: `No | 발생일 | 오류 | 원인 | 교정 | 재발 방지 규칙(가드)`

## 발동 시점 (하나라도 해당하면 즉시)

1. 사람이 결함·오류·누락을 새로 지적했을 때
2. 사실 검증에서 REFUTED 또는 PARTIAL 판정이 나왔을 때
3. 산출물(문서·시트·코드)을 오류 때문에 재작성했을 때

## 절차

1. **기록**: 오류를 교정하기 *전에* `docs/LESSONS.md`에 새 `L###` 행을 추가한다.
   오류·원인·교정·재발 방지 규칙을 한 행에 완결되게 쓴다.
2. **가드 생성**: 교훈을 기록으로 끝내지 않고 강제 수단을 만든다.
   - 문서·설계 단계: 재발 방지 규칙을 관련 문서(체크리스트·정책표)에 반영하고,
     산출물 검증 절차(쓴 뒤 다시 읽어 원본과 대조)를 수행한다.
   - 코드 단계(Phase 0 이후): 검출 체크를 검증 스크립트에 추가하고
     재현 테스트를 테스트 스위트에 추가한다.
3. **교정**: 그 다음에 실제 오류를 고친다.
4. **보고**: 작업 보고에 `L###` 번호를 인용한다.

## 선적용 (예방)

새 작업을 시작하기 전에 `docs/LESSONS.md`를 훑고, 이번 작업에 해당하는
교훈이 있으면 그 가드를 먼저 적용한다. 특히:

- 공공기관 정책 수치 → 하드코딩 금지, `verified_at` 필수 (L001)
- 데이터 소스 → 실존·권리 CONFIRMED 전 로드맵 등재 금지 (L002)
- 외부 시스템 쓰기 → 쓴 뒤 재읽기 대조 필수 (L003)
- 전수 기록 요청 → 원본 문서 전수 대조 (L004)
- 문서 참조(§·수치) → 인용 시점에 원문 확인 (L005)
- 모든 주장 → 상태 라벨(문서 확정/세션 합의/가정/검증필요) (L006)
